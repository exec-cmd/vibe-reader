# vibe-reader: концепт продукта

Статус: черновик от 2026-10-28, составлен по итогам интервью (40 вопросов). Рабочее имя проекта и команды CLI: `vibe-reader`.

## 1. Обзор

Десктопная читалка vibe-reader написана на Rust. Её отличают красивый интерфейс и атмосфера, которая подстраивается под книгу.

Встроенного ИИ в приложении нет. Внешние агенты (Claude Code, Codex, opencode, hermes agent и другие) работают с ним через CLI `vibe-reader` и поставляемые вместе с ним Skills. Через CLI агент анализирует книги и прогресс чтения, обсуждает прочитанное с пользователем, задаёт атмосферу и добавляет иллюстрации.

Читалка рассчитана на три вида текстов: художественную прозу, техническую литературу (код, формулы, таблицы) и Markdown-файлы.

## 2. Платформы и распространение

- Платформы: сначала Linux, затем Windows и macOS. Только десктоп.
- Лицензия: MIT OR Apache-2.0.
- Язык: README, Skills и CLI на английском. Интерфейс локализуется через i18n, русская локализация входит в MVP.
- Каналы: GitHub Releases (бинарники CLI, AppImage) и `cargo install`. Позже AUR, Flatpak, Homebrew и winget.

## 3. Архитектура

Требования: приложение лёгкое и маленькое, ядро лёгкое, программист или агент меняет дизайн без особых усилий.

### Компоненты

| Компонент | Решение |
|---|---|
| Ядро | Отдельный синхронный крейт без GUI, без асинхронного runtime и без тяжёлых зависимостей. Парсит книги, ведёт SQLite, локаторы и статистику, наружу отдаёт очищенный HTML и текст. Форматы и опции подключаются через Cargo features: EPUB, Markdown и TXT включены по умолчанию, FB2 и извлечение текста из PDF подключаются отдельно. Хранилище скрыто за простым интерфейсом. |
| CLI | Бинарник `vibe-reader` на том же крейте ядра. |
| GUI | Tauri (webview). Рендер, подсветку кода, формулы и типографику выполняет webview. |
| UI-код | Без шага сборки: обычные HTML, CSS и ES-модули (JS с типами в JSDoc). Node, npm и фреймворки не используются. Дизайн задан CSS-токенами и файлами пресетов. |
| Переопределение дизайна | Весь UI вшит в бинарник. Файлы из папки конфига перекрывают вшитые и перезагружаются на лету, поэтому агент меняет дизайн правкой одного CSS- или TOML-файла без пересборки. |

Webview выбран потому, что EPUB, HTML и Markdown по сути являются веб-контентом. Нативный GUI на Rust потребовал бы собственного рендерера HTML/CSS и подсветки кода.

### Бюджет ресурсов

| Метрика | Лимит |
|---|---|
| Размер установки (бинарники, шрифты, ресурсы) | не больше 100 МБ |
| Время старта окна | не больше 700 мс |
| Память | жёсткого лимита нет, потребление замеряется в прототипе |

Соблюдение бюджета проверяется в CI. Размер бинарников пока не измерялся.

## 4. Форматы

| Формат | Отображение |
|---|---|
| EPUB, FB2, HTML | Reflow-рендер в webview. |
| TXT, Markdown | Reflow-рендер. Markdown можно импортировать в библиотеку или открыть на месте с live-reload. |
| PDF | Постраничный просмотр через pdf.js. Атмосфера оформляет только пространство вокруг страницы. Текст для агента извлекается через CLI. Reflow появится позже. |

Для технической литературы MVP включает подсветку кода с кнопкой копирования, формулы (KaTeX/MathML), таблицы и большие рисунки с прокруткой и зумом. Mermaid в MVP не входит.

## 5. Данные

### Хранилище

Все данные лежат в одном файле SQLite в XDG data dir: библиотека, прогресс, сессии, заметки и профили атмосферы. Данные хранятся только локально, телеметрии нет.

Файлы книг остаются на своих местах, библиотека хранит ссылки на них. Копирование файла в библиотеку опционально.

### Что записывается

- Позиция в книге.
- Сессии чтения: время, скорость, объём.
- Статус книги: читаю, закончил, бросил.
- Выделения и заметки. Заметки экспортируются в Markdown и JSON.

### Полки

Полки виртуальные: они хранятся в SQLite и не связаны с папками на диске. Полка работает как метка, поэтому одна книга может лежать на нескольких полках. Перенос книги между полками не перемещает файл.

### Локатор

Локатор задаёт единый адрес места в книге, не зависящий от формата. Он состоит из главы, смещения в нормализованном тексте и цитаты-якоря. Локатор работает для всех форматов и переживает мелкие правки файла. Им пользуются заметки, атмосфера на диапазон, цитаты и CLI.

## 6. Интерфейс

Тон по умолчанию: тёплая бумага, редакторская типографика и минимум элементов управления.

### Окно

Приложение живёт в одном окне с тремя состояниями: мини-полка (корешки, поиск, Ctrl+K), полноэкранная библиотека и иммерсивное чтение. Переходы между состояниями плавные.

### Библиотека

Книги показаны типографическими корешками. Цвет корешка берётся из профиля книги, высота заливки показывает прогресс. При наведении книга выдвигается с полки, и рядом появляется карточка с информацией. У файлов без обложки (техлит, Markdown) обложку собирает типографика.

Пользователь группирует библиотеку по своим полкам или по авторам. Групп по статусу («читаю», «закончил») нет: статус хранится как данные для аналитики. Мини-полка показывает недавние книги.

### Чтение

В иммерсивном режиме на экране остаются текст и тонкая полоска прогресса. Панели оглавления, заметок и настроек выезжают по запросу.

Есть два режима: страницы (для прозы) и непрерывная прокрутка (для техлита и Markdown). Режим по умолчанию выбирается по типу книги.

Выделения отображаются тонким подчёркиванием. Выделения пользователя и агента различаются маркером: у агента пунктир и значок. Текст заметки открывается по запросу.

### Типографика

В комплект входят OFL-шрифты с кириллицей: серифы, моноширинные и гротески. Пользователь может выбрать системный или свой шрифт, агент выбирает только из встроенных. Настраиваются размер, ширина строки, интерлиньяж, выравнивание и переносы (RU/EN).

### Управление

Интерфейс рассчитан в первую очередь на клавиатуру и поддерживает мышь и трекпад. Команды доступны из палитры Ctrl+K. Vim-режим включается в настройках.

### Лайт-режим

Лайт-режим открывает файл для быстрого просмотра в том же приложении. Он запускается командой `vibe-reader open file` или через «Открыть с помощью». Окно минимальное: без библиотеки, атмосферы и анимаций, с быстрым стартом. Книга попадает в библиотеку, только если нажать «добавить».

### Макет

Кликабельный макет интерфейса: `docs/design-mockup.html`. Он открывается в браузере и подгружает шрифты из Google Fonts. Макет показывает идеи, итоговая вёрстка будет другой.

## 7. Атмосфера

### Профиль атмосферы

Атмосфера описывается декларативным профилем (JSON или TOML) с валидируемой схемой. Произвольный CSS от агента профиль не принимает. Профиль задаётся на трёх уровнях: книга, глава и диапазон (сцена).

Профиль управляет следующими параметрами:

- палитра;
- пара шрифтов из встроенного списка;
- фоновый слой: лампа и полки, сетка, жалюзи, туман, облака, хребты, а также текстура, градиент или картинка с автозатемнением;
- частицы: пыль, дождь, ливень, снег, боке;
- иллюстрация в начале главы или на полях;
- вариант оформления заголовка главы;
- лёгкие эффекты: зерно, виньетка, мягкий свет.

Контраст палитры проверяется автоматически, так что агент не может сделать текст нечитаемым.

### Пресеты

Пресет состоит из TOML-файла с допустимыми значениями (токены и выбор из наборов вариантов фона, частиц, заголовка и иллюстрации) и необязательного небольшого CSS-файла. Агент, который выбирает пресет по имени, CSS не пишет. Программист или агент, который создаёт новый пресет, может добавить CSS.

Пресет объявляет поддерживаемые варианты оформления в поле `modes`. Например, «дождь» и «гроза» существуют только в тёмном варианте.

Встроенный набор (рабочий): кабинет, терминал, нуар, мягкий, дождь (мрачный), гроза, горный нуар.

### Частицы и движение

Частицы рисуются на одном лёгком canvas на окно с частотой до ~30 кадров/с. Анимация останавливается, когда вкладка скрыта, в лайт-режиме и при `prefers-reduced-motion`. Вспышка молнии слабая и случается не чаще раза в 6 секунд. Нагрузку и влияние на бюджет нужно замерить в прототипе, особенно на WebKitGTK.

Кроме частиц, движение ограничено мягкими переходами: смена темы между главами, заставка главы, листание. Все анимации учитывают `prefers-reduced-motion`.

### Иллюстрации и обложки

Агент или пользователь передаёт файл или URL, а `vibe-reader art add` копирует картинку в хранилище и привязывает её к локатору. Принимаются растровые изображения и SVG без скриптов, размер ограничен. Генерации картинок в приложении нет.

### Звук

Звука в MVP нет. Схема профиля оставляет место под поле `sound`.

## 8. CLI и агенты

### Режимы работы

CLI и GUI используют общее ядро и работают в двух режимах:

- offline: CLI работает с библиотекой напрямую, GUI не нужен;
- live: если GUI запущен, CLI управляет им через IPC (позиция, выделение, смена атмосферы на лету).

IPC только локальный: unix socket или named pipe с правами владельца. Сетевого порта нет.

### Формат вывода

Если stdout не TTY, CLI выводит JSON, в терминале показывает форматированный текст. Формат задаётся явно флагами `--json` и `--md`.

### Безопасность и права агента

- Агент может читать всё и записывать заметки, закладки, атмосферу и иллюстрации. Деструктивных операций над книгами у агента нет.
- Текст книги в выводе помечается как данные. Skills требуют от агента считать его недоверенным, чтобы снизить риск prompt injection из содержимого книг.

### Обсуждение книги

Пользователь запускает агента в терминале рядом с читалкой. Агент получает контекст командой `vibe-reader context`: текущую главу, выделение, позицию и заметки. Встроенный терминал и кнопка «обсудить» появятся позже.

### Общие правила команд

- Защита от спойлеров по умолчанию. `read`, `search`, `context` и другие команды отдают только текст до текущей позиции пользователя. Дальше можно читать только с явным флагом `--allow-spoilers`.
- Порционный вывод. Текст отдаётся частями в пределах лимита токенов (`--max-tokens`) с курсором для продолжения, поэтому агент не получает всю книгу разом.
- Авторство. Каждая запись агента помечена автором и откатывается командой `undo`. Удаление мягкое.
- Согласие на профиль. Профиль пользователя доступен агенту только с явного согласия, которое задаётся в конфиге по разделам: привычки, жанры, скорость.

### Команды

Группы 1–3 задал автор проекта, группы 4–8 предложены в ходе интервью и утверждены. Имена команд рабочие.

**1. Полки**

- `shelf create | rename | delete | list`
- `shelf add <полка> <книга>`, `shelf remove <полка> <книга>`

**2. Книги и арт**

- `add <файл|url>`, `remove <книга>`, `list`, `show <книга>`, `open <файл> [--lite]`
- `art add <книга> --locator <место> <файл> [--as page|chapter|margin|cover]`, `art list`, `art remove`

Вариант `--as page` вставляет в книгу страницу-иллюстрацию: так реализуется требование «добавить страницу арт».

**3. Чтение книг агентом**

- `toc <книга>`
- `read <книга> [--chapter | --locator | --range]`
- `read --continue`: продолжает чтение с курсора агента, который ведётся отдельно от курсора пользователя.
- `search <книга> <запрос> [--regex]`
- `context`: текущее место пользователя (глава, выделение, позиция, заметки).
- `stats <книга>`: число слов и глав, оценка времени чтения.

**4. Заметки и закладки**

- `note add | list | edit | delete`
- `bookmark add | list`
- `highlight add`
- `export notes --md | --json`

**5. Память агента о книге**

`memory set | get | list --book <книга>`. Агент записывает персонажей, термины, хронологию и свои выводы с привязкой к локатору. Записи сохраняются между сессиями, и агенту не нужно перечитывать книгу заново. Приложение ничего не вычисляет само, оно только хранит записи.

**6. Прогресс и профиль читателя**

- `progress <книга>`
- `sessions [--period week]`
- `stats --reader`: скорость, время суток, объём за период.
- `recap <книга>`: что прочитано с прошлой сессии, вместе с заметками пользователя.
- `status set <книга> reading | finished | dropped`

Приложение отдаёт цифры. Выводы вроде «вы читаете быстрее вечером» или «книга стопорится на главе 7» делает агент.

**7. Атмосфера** (см. раздел 7)

- `atmosphere get | set | clear [--book | --chapter | --range]`
- `preset list | show | validate | install`

**8. Живое окно и служебные команды**

- `live position | selection | goto <локатор> | highlight`
- `gui status`
- `skills install | list`
- `config`, `doctor`, `undo`

**Позже:** карточки для запоминания и тесты (`quiz`), частотные списки и конкорданс (`wordfreq`, `concordance`).

### Skills

Skills поставляются как файлы SKILL.md и устанавливаются командой `vibe-reader skills install`.

| Skill | Назначение |
|---|---|
| `reader-cli` | Общая работа с CLI и правила безопасности. |
| `reader-analyze` | Анализ книги и прогресса. |
| `reader-discuss` | Обсуждение с контекстом текущего места. |
| `reader-atmosphere` | Подбор тем, атмосферы по главам, иллюстраций. |

## 9. План разработки

0. Прототип: пустое окно Tauri со статичным HTML. Замерить размер установки, время старта и поведение CSS columns в WebKitGTK. Проверить подмену файлов UI из папки конфига.
1. Ядро и CLI в режиме offline: EPUB, Markdown, TXT, SQLite, локаторы, `context`, Skills.
2. GUI-ридер (Tauri, UI без сборки) и лайт-режим.
3. Атмосфера и live IPC.
4. FB2 и PDF.

## 10. Риски

| Риск | Что делать |
|---|---|
| На Linux Tauri использует WebKitGTK. CSS columns для постраничного режима, анимации и фильтры могут вести себя там иначе, чем в Chromium на Windows. | Проверить в прототипе до больших вложений в GUI. |
| Подмена вшитых файлов UI файлами из папки конфига с hot-reload в Tauri не проверена. Скорее всего понадобится собственный обработчик схемы адресов. | Проверить в прототипе. |
| Шрифты и пресеты занимают место в бюджете 100 МБ. | Ограничить набор шрифтов. |
| UI без сборки и фреймворка: состояния и компоненты пишутся вручную, код может разрастись в самодельный фреймворк. | Следить за объёмом UI-кода. |
| Содержимое EPUB/HTML может содержать скрипты и внешние ресурсы. | Рендерить без выполнения скриптов и без загрузки внешних ресурсов. |
| Prompt injection из текста книги. | Пометка «это данные» в CLI и правила в Skills. Полной гарантии они не дают. |
| Лицензии парсеров FB2 и PDF не проверены. | Проверить до выбора зависимостей. |

- Набор и лицензии встроенных шрифтов.
- Формат и схема экспорта заметок.
- Разделы и формулировки согласия на доступ агента к профилю пользователя.
- Точные имена и флаги команд (сейчас рабочие).
- Что показывает мини-полка (сейчас предполагаются недавние книги).
- Нужен ли пятый Skill для правки дизайна и пресетов агентом (например, `reader-design`).
